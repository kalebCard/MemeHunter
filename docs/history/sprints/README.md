## 🛠️ 3. Reglas de Estandarización de Archivos de Sprint

Todos los planes de sprints deben cumplir con la siguiente especificación canónica:
1. **Nomenclatura:** Prefijo numérico ordenado `NN_SPRINT_...` (ej. `06_SPRINT_030_...`).
2. **Encabezado YAML:**
   - `id`: Formato `HIST-SPRINT-XXX`.
   - `category`: `history/sprints`.
   - `version`: Versión semántica del documento.
   - `status`: `COMPLETED` o `CERTIFIED`.
   - `references`: Lista de dependencias directas con rutas canónicas relativas.
3. **Cero Enlaces Rotos:** Prohibido el uso de rutas absolutas de desarrollo (e.g. `OneDrive`). Todas las referencias a código o tests deben utilizar rutas relativas al proyecto o sintaxis Markdown estándar.
